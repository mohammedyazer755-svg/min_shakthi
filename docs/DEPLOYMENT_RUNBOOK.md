# Deployment and operational runbook
Planning instructions; nothing has been deployed by this package. Use Windows 11 PowerShell, VS Code, Git, Node 24 LTS and npm. Pin exact patched Node/npm/dependency versions in Phase 1; verify on CI. Docker Desktop is needed only for the isolated integration stack. No company credentials in chat, committed project files or test fixtures.

The test stack uses only disposable local credentials generated by its harness. Use an OS secret manager/secure runtime injection for real credentials. .env.example lists names with empty values; never fill it with secrets. Configuration validation should explain missing variable names without printing values.

## Provision order
1. Company owner creates/reviews repository and provider projects; assign maintainers and least-privilege access. Preserve legacy deployment until V2 acceptance. Do not migrate hardcoded legacy accounts.
2. Create managed PostgreSQL in the backend region. Enable backup policy, private connectivity where available, restricted DB users and encrypted transport. Record provisioned version and capacity; no fabricated service URL.
3. Create one paid always-on Render **web service**, repository root build context. Build `npm ci && npm run build:server`; start `npm run start:server`. These scripts are implemented in Phase 1/2. Set NODE_ENV, broker, DB, auth and origins using Render environment manager. Add persistent disk mounted /var/data. Keep instance count one.
4. Run additive DB migrations through a controlled release job; migrations require reviewed backup/rollback plan. On disk-backed service do not assume pre-deploy job can access disk; only process startup touches spool. Bootstrap admin via a one-time server-side command with secure interactive input/invitation, no default password.
5. Set Render process health endpoint `/health/live`; monitor `/health/ready` and privileged diagnostics externally for broker/DB/spool problems. Do not let DB downtime endlessly restart the MQTT ingestor.
6. Create Vercel frontend from the monorepo. Build context must include shared packages: root `npm ci`, build `npm run build:web`, output `apps/web/dist`. Put an effective SPA fallback at the configured Vercel project root. Verify `/overview`, `/history` and `/login` direct navigation. Public VITE_API_BASE_URL points to actual backend HTTPS URL. Rebuild frontend after changing public build-time vars.
7. Prefer app/api custom subdomains under a company-controlled parent domain. Configure DNS and HTTPS, exact CORS/Origin rules, Secure HttpOnly refresh cookies; test desktop/Android/iPhone. With default cross-site domains expect blocked third-party cookies on some browsers; re-login is the honest fallback until same-site setup is ready.
8. Register devices and confirmed raw-channel mappings through admin workflow. Expected interval is per-channel, not merely board message rate. Do not auto-enroll arbitrary incoming IDs.
9. Run isolated smoke checks first, then authorized read-only hardware verification and measured latency. Only switch users after acceptance evidence. Keep billing disabled unless its validation gate passes.

## Operational dashboards and alerts
Track accepted/rejected packets by reason, last valid receipt per channel, broker connect/SUBACK, reconnect count, event-loop lag, active sockets, authorization failures, spool bytes/oldest age, DB batch latency, persistence lag, explicit loss counters, receipt-to-render distributions and frontend errors. System heartbeat every 5s; sanitize public health response. Infrastructure alerts do not depend solely on the affected browser. Log eventId/requestId/commit/environment; redact all authorization headers and credentials. Rate-limit malformed-payload logging.

## Troubleshooting
| Symptom | Inspect first | Action |
|---|---|---|
| Website loads but no live data | Network tab backend HTTPS URL, socket handshake/auth, subscription status | Fix public URL/allowlist/session; do not point browser at port 1883 |
| Broker connected but no data | SUBACK, exact topic, registered ID, parse error reason, device publish interval | Ask hardware owner to confirm publisher; avoid production test-packet injection |
| One board overwrites another | Composite keys, authorized room and mapping versions | Reproduce T02; reject channel-only state |
| Values frozen but green | Receipt age, retained status, heartbeat age | Verify freshness state machine; socket connection alone is insufficient |
| History unavailable/live present | DB connectivity/spool depth | Restore DB, replay and reconcile event IDs; show delayed persistence |
| Repeated sign-in on mobile | Cross-site cookie policy and domain configuration | Configure same-site domains; never persist bearer token in localStorage |
| First packet delayed | ESP32 boot/publish timing, subscriber readiness and service sleep | Use always-on service and measure each stage independently |

## Backup, rollback and recovery
Daily DB backup; isolated restore drill verifies users, mappings, telemetry row counts and reports. Do not export passwords/tokens into handover evidence. Snapshot/backup spool volume according to provider operations; spool cannot restore a lost database by itself. Document actual RPO/RTO from drill.

Deploy additive backend contracts first, compatible web second. Keep last good backend/web commits available. Roll back binaries only when schema-compatible; prefer forward corrective migration for destructive schema changes. Before disk-backed restart drain/fsync spool, record cursor and downtime. After restart verify new epoch, recovered pending events, subscription and newest actual packet. Flag downtime as a potential gap. Broker plaintext/TLS decision and finite outage durability remain explicit handover risks.

## Final handover
Provide editable repository and lockfile, clean clone instructions, tests, migrations, environment-name inventory, architecture/data model, account/role ownership, device mapping evidence, calibration/billing decision, latency results, browser matrix, backup/restore record, known limitations and operational owner. Credentials are transferred through the company’s secure credential manager, never this documentation.
