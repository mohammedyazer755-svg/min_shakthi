# ADR-001: Persistent ingestion service
Accepted for planning, 16 October 2026.

The broker must have a subscriber even when all browsers are closed. Deploy one paid always-on Render web service combining Node MQTT, Express and Socket.IO; use a persistent disk for the bounded durable spool and managed PostgreSQL for long-term data. Vercel hosts only the static React build.

A sleeping web service or request-lifetime function cannot satisfy continuous ingestion. A standalone background worker would need a separate public API/socket service and coordination, which adds unnecessary initial complexity. A VPS is an acceptable equivalent when its operations/backup ownership is established.

Consequences: pay for continuous compute; monitor process, subscription and persistence separately; disk-backed deployments may interrupt service and are not a zero-downtime promise. One subscriber instance only. Future horizontal scale requires an explicit ADR for ingestion ownership, fan-out and replay. No client TCP MQTT and no frontend credentials.

References: https://render.com/docs/free ; https://render.com/docs/web-services ; https://render.com/docs/disks ; https://socket.io/docs/v4/delivery-guarantees/ .
